# 网络分析

## 系统级检查

从链路、socket 和重传健康状态开始：

```bash
sar -n DEV 1 3
sar -n TCP,ETCP 1 3
ss -s
ip -s link
```

关注点：

- 接口吞吐量和包速率
- 丢包、错误、溢出
- 重传和复位
- 监听队列和已建立 socket 增长
- 积压压力或连接状态异常

有用的辅助检查：

```bash
netstat -s
ss -lntp
nethogs
iftop
```

## 进程深入分析

识别拥有繁忙或不健康 socket 的进程：

```bash
ss -tpn
ss -lntp
nethogs
```

如果需要包级证据：

```bash
tcpdump -i <iface> -nn -s 128 -c 200
ping <target>
```

`tcpdump` 应该简短且有界。保持包计数上限，除非必要否则避免全负载捕获。

主动负载测试（非生产优先，需要明确授权）：

```bash
iperf3 -c <target>
```

## 解读

- 高重传、丢包、复位或积压溢出表明网络路径或内核 TCP 压力。
- 高吞吐量但正常重传可能是健康的；在称之为瓶颈前检查延迟和排队。
- 很多 `TIME_WAIT`、`SYN_RECV` 或接受队列问题可能是连接管理问题而非原始带宽短缺。
- 如果一个进程拥有大部分热门 socket 或驱动异常连接抖动，该进程是应用程序触发因素。
- 高软中断 CPU 加上网络流量通常意味着瓶颈在内核网络或中断处理中。

## 内核态 vs 应用态

- 应用态：连接风暴、糟糕的 socket 使用、小写、慢读或低效协议行为源自某个进程。
- 内核态：软中断、TCP/IP 栈、积压处理、驱动/NIC 行为或 socket 缓冲区压力占主导。
- 混合情况：应用程序可能触发内核网络压力。同时报告内核热点并指出导致它的进程。
