# I/O 分析

## 系统级检查

从文件系统容量和磁盘延迟开始：

```bash
df -h
df -i
iostat -xz 1 3
vmstat 1 5
```

关注点：

- `%util`：设备忙时间
- `await`：端到端 I/O 延迟
- `svctm`（如果可用）
- `r/s`、`w/s`、`rkB/s`、`wkB/s`
- 队列深度以及延迟是否随利用率上升
- inode 耗尽或文件系统满

有用的辅助检查：

```bash
pidstat -d 1 3
iotop -oPa
```

## 进程深入分析

找出产生 I/O 或 I/O 延迟高的进程：

```bash
pidstat -d -p ALL 1 3
iotop -oPa
```

如需要，检查文件和块行为：

```bash
timeout 10s strace -tt -T -p <pid>
timeout 15s filetop
timeout 15s biotop
timeout 15s biolatency
```

以上命令仅作为升级步骤，需要明确授权，因为它们可能需要提升权限并可能增加开销。

## 解读

- 高 `%wa` 加上高磁盘 `await` 通常意味着存储是瓶颈。
- 高 `%util` 但低吞吐量仍可能意味着由于小随机 I/O 导致的慢设备。
- 磁盘满或 inode 耗尽看起来像应用程序缓慢，但本质上是 I/O/文件系统问题。
- 一个进程主导读写或显示高 `iodelay` 是可能的应用程序触发因素。
- 如果存储设备平静但进程卡在文件操作中，检查文件系统锁、元数据开销和系统调用计时。

## 内核态 vs 应用态

- 应用态：进程发出低效的读写模式、同步密集型行为或过多的日志/检查点。
- 内核态：块层、文件系统、页面缓存回写、设备驱动或挂载/文件系统行为主导延迟。
- 混合情况：进程可能产生压力，而可见的等待时间累积在内核 I/O 路径中。同时明确报告两方面。
